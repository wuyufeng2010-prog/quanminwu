# 第一阶段扩展接口与接入边界

`src/lib/platform-contracts.ts` 只定义 TypeScript 协议，复用现有课程进度、节拍和问题字段。**没有实现登录、服务器、数据库、支付、教师后台或云端问答，也没有被页面用来生成假登录或假权益。** 文件可供后续 Next.js 服务端适配层实现，不需要拆分微服务或增加依赖。

## 当前功能与未来服务的区别

| 模块       | 当前原型                                   | 未来适配接口                                                            |
| ---------- | ------------------------------------------ | ----------------------------------------------------------------------- |
| 登录       | 无账号，不识别真实用户                     | `AuthenticationProvider`：读取会话、进入登录流程、退出                  |
| 学习进度   | 当前浏览器 localStorage，可恢复和清除      | `LearningProgressProvider`：当前账号的云端读取、带版本保存、删除        |
| 课程权益   | 演示课程和技术测试片，无购买流程           | `CourseAccessProvider`：查询服务器已有权益，不创建订单或付款            |
| 学员答疑   | 本机问题、文件名和固定示例反馈，无教师收件 | `TeacherQuestionProvider`：当前学员的文字问题、提交状态、真实回复与删除 |
| 教师工作台 | 没有真实教师账号和服务端管理界面           | `TeacherWorkspaceProvider`：负责课程的节拍确认、答疑列表与教师回复      |

现有 `PlaybackAuthorizationProvider`（`learning-types.ts`）继续负责未来短期播放授权与服务器水印会话；`CourseAccessProvider` 的查询结果不能代替实际视频授权。`BeatAnalysisProvider` 仍只是未来分析接口，不能让未审核的结果自动变成正式教学内容。

## 服务端必须负责的事项

- 通过真实会话识别当前用户，不接收浏览器指定的学员 ID 作为身份依据。密钥、访问令牌、支付验证和教师权限均不写入 localStorage 或前端代码。登录回跳只允许本应用受信地址，校验登录流程状态；写操作需有会话与请求来源保护。
- 每次读写检查用户、课程及资源权限。学员只能访问自己的进度和问题；教师只能查看获分配课程的问题并确认相应时间轴。隐藏按钮或客户端角色判断不构成权限校验。
- `CourseAccess` 由可信数据库和服务端规则计算。`reason: purchase` 仅是未来已验证权益的结果类型，当前没有付款成功记录或购买功能；客户端不能自行授予权益。授权过期后重新判断，私有媒体使用短期链接。
- 对输入执行运行时校验；TypeScript 类型不能验证网络请求。校验课程存在、有限且非负的时间值、速度范围、视角、循环边界、问题长度及分页上限。对权限不足或服务不可用返回明确错误，不返回虚构成功。
- 对问题执行必要的内容处理、限流、访问控制和删除/保留规则。此阶段文字问答协议不包含文件上传；现有 `localVideoName` 不迁移成附件，更不能当成视频已上传。未来上传需单独设计私有存储、文件校验与短期访问许可。

## 进度同步与迁移

`CloudLearningProgress` 复用 `LearningProgress`，增加服务器 `revision` 与 `savedAt`。新记录的 `expectedRevision` 为 `null`；更新必须附上读取时的版本。服务端原子比较版本，冲突返回 `conflict`；客户端先重新读取并让用户选择继续位置，不能按浏览器时间戳静默覆盖另一设备。

`technical: true` 表示技术片练习，不能计为正式课程完成、学习时长认证或课程权益。匿名浏览器记录没有账号隔离，接入后必须经用户确认才能迁入当前账号；不能自动迁移共享设备上的历史记录或本机问题。退出账号应清理内存中的私人数据，按隐私策略决定是否保留本机演示记录。

## 教师节拍确认

`StoredMusicTimeline` 保存时间轴版本及服务器确认记录。`confirmTimeline` 由有权限的教师触发；服务器检查拍点顺序、拍号、乐句范围、媒体时长和课程版本，并原子更新版本。成功后返回 `reviewStatus: teacher-confirmed` 与非空 `confirmation`，教师 ID 和确认时间由服务器生成，不信任浏览器传入。

正式发布必须同时具备服务器审核记录、对应授权教学素材和课程版本。原型中的 `demo-only` 时间轴不构成正式审核，本阶段没有实现教师确认操作；换素材或修改拍点后需重新审核。统一课程时间与各视角 `timelineOffset` 的含义保持不变，避免切换视角后错拍。

## 接入顺序

1. 选择单体后端存储与认证方案，在 Next.js 服务端实现会话与课程访问控制，补充服务端权限验证。
2. 实现带版本的学习进度，明确匿名数据迁移与删除流程。
3. 接入授权教学素材、短期播放凭证和教师确认记录，验证真实多视角时间轴。
4. 实现课程内一对一文字答疑和教师工作台，再单独评估练习视频上传。

真实支付、AI 评分、教师市场、社区、商城与复杂微服务不属于本阶段。以上协议尚未接入，接入后仍需数据库迁移、运行时验证、认证和访问控制测试，不能将本次类型检查视为服务端验收。
